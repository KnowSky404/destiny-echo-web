# 命运残响 · Echoes of Destiny

**一款运行于浏览器的二次元弹幕射击 Roguelike 游戏。**

> 每一场命运的轮回，都可能出现意料之外的展开。

命运残响（Echoes of Destiny）是一款面向桌面与移动浏览器的轻量级 Web 游戏。玩家将在屏幕底部区域控制角色移动，在持续不断的敌潮与弹幕中生存，通过击败敌人、开启宝箱、选择卡牌和组合强化，逐步构筑属于自己的战斗流派。

游戏以严肃的二次元幻想氛围为基础，融合随机成长、卡牌构筑与荒诞的战斗效果。随着项目发展，游戏将逐步引入原创角色、异常事件、互联网梗与更多风格各异的世界观。

**项目目前处于早期开发阶段。本文档描述的是项目定位与计划，不代表相关功能已经实现。**

## 核心设计

### 战斗与生存

- **纵向弹幕射击：** 玩家主要在屏幕底部区域移动，躲避敌人攻击并持续输出。
- **持续战斗：** 通过合理走位、攻击强化与技能组合应对逐渐增强的敌潮。
- **首领挑战：** 在阶段性战斗中面对具有独特攻击方式的强敌。
- **操作简洁：** 优先考虑简单直观的操作方式，降低上手门槛。

### Roguelike 与卡牌构筑

- **随机奖励：** 击败敌人、开启宝箱或完成战斗事件，获得不同奖励。
- **卡牌选择：** 在每局游戏中选择强化卡牌，形成不同的成长路线。
- **流派组合：** 鼓励攻击、弹幕、暴击、生存和特殊效果之间的协同。
- **局内成长：** 随着战斗推进逐步强化角色，应对更高强度的敌人。
- **随机事件：** 引入意外奖励、特殊挑战和不按常理出牌的效果。

### 严肃幻想与荒诞效果

游戏的视觉呈现与世界观将保持二次元幻想作品的质感，但实际战斗可以充满意料之外的效果。

例如，某些强化可能产生超规格的弹幕组合，某些卡牌可能带来意想不到的连锁反应，特殊事件也可能彻底改变本局游戏的策略。

未来计划逐步扩展原创幻想设定、互联网梗、隐藏内容与特殊挑战，让每局游戏都具有不同的体验。

## 设计原则

1. **浏览器优先：** 以 HTML、CSS 和 JavaScript 为基础，优先实现轻量、易部署的 Web 游戏。
2. **跨设备体验：** 兼顾桌面键鼠操作与手机触屏操作，采用适配不同屏幕尺寸的布局。
3. **玩法优先：** 先完成可玩的核心战斗循环，再逐步扩展卡牌、敌人、首领与事件系统。
4. **模块化设计：** 尽量分离战斗逻辑、游戏数据、输入处理、界面渲染与配置，降低后续扩展成本。
5. **可扩展内容：** 优先使用数据驱动的方式组织敌人、卡牌、奖励与关卡配置。
6. **原创与合规：** 以原创品牌和可合法使用的素材构建公开发布版本，避免未经授权使用第三方作品的受保护素材。

## 开发路线图

以下为计划中的开发阶段，实际进度以代码和可验证的运行结果为准。

- [ ] **Phase 1 — Playable MVP**
  - 建立基础游戏页面与渲染循环。
  - 实现角色移动、敌人生成、自动攻击与碰撞判定。
  - 实现生命值、受伤、死亡与基础胜负流程。
  - 支持桌面键盘与移动端触屏操作。

- [ ] **Phase 2 — Roguelike Core**
  - 实现经验、升级与随机卡牌选择。
  - 实现宝箱奖励与局内强化。
  - 建立可组合的卡牌效果与基础流派。
  - 增加敌人波次与首领战。

- [ ] **Phase 3 — Content & Balance**
  - 扩充敌人、卡牌、武器与特殊事件。
  - 调整难度曲线、奖励概率与流派平衡。
  - 建立基础游戏数据配置机制。

- [ ] **Phase 4 — Polish & Expansion**
  - 优化动画、特效、音效与游戏反馈。
  - 改善移动端适配、性能和操作体验。
  - 逐步加入原创幻想设定、隐藏内容与荒诞事件。
  - 评估静态网页部署与后续发布方案。

## 技术方向

初期优先考虑：

- **HTML5**：游戏页面与基础结构。
- **CSS**：界面布局、响应式设计与动画。
- **JavaScript**：游戏状态、战斗逻辑、输入处理与随机系统。
- **Canvas 2D**：候选的游戏渲染方案，适合弹幕、粒子与高频画面更新。

具体技术选型以 MVP 的实现成本、运行性能和维护难度为依据，不预先引入非必要的框架或服务端依赖。

## 项目状态

**Status: Early Development**

当前优先目标是建立最小可玩版本，验证移动操作、自动攻击、敌潮生存、随机奖励与卡牌构筑能否形成完整且有趣的游戏循环。

尚未实现或未经验证的功能不会标记为已完成。
