# PRE 数值实验室

PRE 是独立 Worker `destiny-echo-web-pre`。只有 `pre` 构建包含「PRE · 数值调试」按钮；普通开发和 PRO 构建不加载调试模块、方案存储或可写调试入口。数值方案保存在浏览器当前 origin 的 `localStorage`，没有远端配置写入接口。相同浏览器配置文件下的 PRE 标签页共享已保存方案，但已运行的测试固定版本，不因其他标签页保存而热切换。写入通过 Web Locks 串行处理；其他标签页已更新存储时拒绝旧页覆盖，需先导出草稿再刷新。另一浏览器、无痕上下文与生产站点各自隔离。

## 使用流程

1. 在 PRE 开始游戏，打开数值调试器。战斗暂停，关闭后手动继续。
2. 「玩家与构筑」编辑生命、护盾、状态、基础属性覆盖和卡牌层数。实际攻击间隔、弹数、暴击、吸血等仍遵循游戏上限，面板展示羁绊后的实际战斗数值。属性覆盖优先于卡牌成长，清除覆盖即可看到真实构筑数值。
3. 「敌人与出怪」分别操作现有单位和后续生成规则。修改出怪或援军间隔会重新启动对应的剩余间隔计时；保留构筑重开同样采用修改后的间隔。改现有生命上限会保持剩余生命比例，也可指定当前生命。移除没有击杀收益；移除首领后仍须清空其他敌人才结算。补怪保留首领位置且不超过物理容量。
4. 「关卡控制」可保留当前生命、构筑与临时出怪规则重开本关，或恢复入关快照，包括生命、卡组、累计进度及全部随机状态。两种方式清空战场、本关时钟与旧奖励；实体 ID 和奖励令牌不倒退。跳关默认保留构筑，也可选择新角色；第 5 关为无尽第 1 层。
5. 「方案版本」调整可持久化的参数，保存新版本，再启用测试。启用按指定种子重开整局；草稿编辑不会改变正在运行的版本。刷新保留草稿、版本及选中版本，战斗不保存。
6. 测试满意后导出 JSON，交给维护者应用。导出草稿和导出已保存版本使用同一格式；草稿导出分配新标识，保存版本的导出保留固定标识和版本号。文件不包含临时属性、构筑或战斗进度。临时操作不会自动抄入持久方案。

重建构筑保留真实获取顺序，减少层数时移除该卡最近的获取事件。新增卡牌的即时治疗或护盾只执行一次，重算不重复赠送；删卡不回溯已发生的治疗或承伤，降低生命上限会夹紧当前生命。整局重开清除临时修改，关卡推进清除临时出怪覆盖。

## 方案规则

JSON 包含 `schemaVersion: 2`、`baseline: "balance-v2"`、`id`、`revision`、`name` 和 `payload`。载荷包括完整初始玩家数值、六类敌人的基础参数、无尽参数、`evolution`（训练门槛、基础二次成长、分段休止、蓄力/后摇/弱点、百分比额度与实效攻速下限）、三种奖励来源卡池及最多200条关卡规则。v2调试表单隐藏不再参与推导的旧指数成长字段；它们仅保留在JSON中供溯源。单卡效果、叠加上限、羁绊规则和对象池预算继续由代码定义。当前源码另固定第五层后的生命尾项、第4层起双精英、本次预警确认与起势、深层吸血与共享战斗回复额度、高星/深层百分比抗性、波次编组及单次普通受击上限；这些不是新增可编辑字段，旧方案导入也使用当前代码规则，不会恢复旧战斗。

- 关卡规则使用从 1 开始的 `from` 与包含边界的 `to`；`null` 表示持续到任意后续关卡。优先级为全局（1 至无限）、区间、单关。同优先级规则不得重叠。
- `stage` 只覆盖显式设置的字段。数量以四车道为基准换算，并限制在场地实际容量；预算或首领时间变化会重新计算出怪间隔，显式间隔覆盖自动推导。单关直接覆盖优先于无尽推导；无尽以实际第四关覆写后的生命与首领值为锚点，因此第四关覆写会同步影响无尽基准。
- 临时修改无尽 `enemyCount` 会重排遭遇导演的实际计划：已出场的基础信用和已结束怪群不追回，当前及未来怪群均分剩余请求量，余数优先分给较早怪群。请求值低于已花信用时，有效预算夹紧为已花；已无剩余怪群则本关只保留已花部分。面板显示有效预算，临时覆写保留原请求值，保留构筑重开会以该请求值重新建整关预算，恢复入关快照则撤销临时覆写。
- `endless.supplies` 支持0–12。前三段完成后累计应领数为 `floor(N×k/3)`（k=1/2/3），每次补齐差额；N=3时各一次，N=0时没有补给，较大N可以同段连续选多次，选牌期间战斗不推进。第4层起双精英共用一个段落边界，不追加份数。
- `kindWeights` 非空时替换本范围的小怪权重；`null` 表示继承其他匹配规则，未配置时沿用原来的均衡轮换。
- 每种奖励来源各有 `guided`（原引导规则加权）与 `weighted`（纯权重）模式，关卡规则可完整覆盖一个来源的策略。权重未设置为 1，0 排除；纯权重模式包括史诗，不使用额外晋升掷骰。首领奖励仍为最多两项锻体和一张残响；其锻体权重也用于训练分自动锻体；没有合格锻体时消耗已达到的里程碑，记录跳过次数，不在后续关卡补发。
- `firstStageRestriction` 默认保留首关四类输出卡池与首关禁吸血锻体；显式关闭可测试其他首关卡池。资格、去重及叠加上限继续生效。权重比例不是最终三选一出现概率。
- 候选不足三项时显示实际数量；全部耗尽时显示无可用奖励，并通过一次性令牌继续，不补入已排除卡牌。
- 敌人的基础首领生命默认 2000，作为各关首领生命的倍率基准；实际首领生命为关卡生命乘以该值除以 2000。攻击与渲染读取单位生成时的参数，后续出怪调整不追改已有单位。

v2使用独立的 `echoes:pre:balance:v2` 存储，原 `echoes:pre:balance:v1` 保留不写回。打开新版不会自动启用旧选中方案；“v1方案备份与迁移”可导出原始存储/方案，或显式迁移为新身份的独立v2版本。迁移保留已知数值，补齐新evolution参数，不替换草稿、选中版本或当前战斗；之后须另行选择测试。旧回放仍需旧代码与指纹。损坏的v1原始存储仍能备份，不阻断v2保存。

导入校验版本、基线、字段、已知卡牌 ID、有限数值、整数、范围和权重。失败不替换当前草稿；导入成功作为新方案草稿，避免覆盖现有版本。浏览器保存最多 100 个版本；删除后仍保留该方案已使用的最高版本号，刷新或恢复旧草稿均不会重复使用版本号。存储不可用、额度耗尽或浏览器缺少跨标签页锁时明确提示，仍可在当前页试验和导出；缺少锁时不写入共享存储。共享保存失败不会生成可导出的固定版本，可改为导出带新标识的草稿备份。

## 应用到正式配置

在独立 worktree 中执行：

```sh
bun run balance:validate /path/to/echoes-balance.json
bun run balance:apply /path/to/echoes-balance.json
bun run docs:generate
bun run docs:check
bun run typecheck
bun run lint
bun test
bun run build
```

应用命令将校验后的方案写入 `src/data/balance/official.json`；初始值 `null` 表示沿用原始默认数值。必须人工核对 `scripts/game-guide.ts`、游戏内帮助和相关规格中的叙述，不能用生成代替语义检查。命令不会部署、提交或发布 Wiki。后续按仓库审阅、Wiki 与环境发布流程交付，先验证 PRE，再在明确授权下发布 PRO。

## 开发和验证

```sh
bun run dev:pre
bun run build         # dist，PRO
bun run build:pre     # dist-pre，PRE
bun run test:browser
bun run deploy:check:pre
bun run deploy:pre
```

两个构建目录独立；PRE 发布入口显式构建 `pre` 模式，并打包 `dist-pre`。`test:browser` 会先构建 PRE，直接使用 Playwright CLI 时须先准备两种构建。默认本地服务器保持 loopback。测试覆盖真实构建的编辑、重开、配置往返、刷新保留、独立浏览器隔离，以及 PRO 不包含调试代码。浏览器自动化不代表真机或长时间体验验收。

## 自动化实验与人工复核

[Balance Simulator V1](balance-simulator.md) 直接接收本实验室导出的固定版本 JSON；CLI 输出的完整候选方案通过实验页“导入候选为独立版本（保留草稿）”保存为新标识的固定版本，仍使用同一个 `parseProfile` 和原写锁，不改变原草稿、选中版本、正在运行版本或已保存历史。原“导入配置 JSON”仍是显式替换当前编辑草稿的操作。选中已保存版本、草稿、正在运行版本在界面中分别显示。

「实验/复核」提供选中固定版本导出、校验并载入 `summary.json` / 单局 case。摘要只展示统计；case 显示方案、种子、策略、逻辑布局、终止结果和关键诊断，校验完整内容指纹。准备人工复核按同方案、同种子、同逻辑宽度重建新局并暂停，独立 one-shot sessionStorage 不修改已有 localStorage 草稿、版本或选中状态。实验数值失效会明确标为状态不可用，不将传输占位数当真实结果。

重新开局是人工试玩准备，不是相同动作自动播放；CLI `balance:replay` 才验证相同策略的确定性事件和结果。浏览器不保证代码指纹与 CLI 一致，不是任意战场存档恢复。功能仍为 PRE-only，PRO/普通dev无实验入口、运行器或报告模块，也不向window暴露可写World。实验数据导入不修改远端配置；Wiki同步与环境发布分别核验。
